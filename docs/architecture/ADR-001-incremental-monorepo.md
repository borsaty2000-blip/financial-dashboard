# ADR-001: Incremental Monorepo Instead of Big-Bang Rewrite

## الحالة

مقبول — 14 سبتمبر 2026.

## القرار

نحتفظ مؤقتاً ببنية `client/`, `server/`, `server/python-services/`, و`BorsatyMobile/`، ونضيف الحزم المشتركة والوثائق وCI أولاً. لا ننقل أو نحذف الملفات الحالية حتى يمر البناء المزدوج ويثبت التكافؤ.

## السبب

إعادة الهيكلة الشاملة في منصة مالية تحتوي على بيانات سوق ومصادقة وSocket.io وPrisma قد تنشئ أعطالاً صامتة في المسارات أو أسرار البيئة أو النشر. الانتقال التدريجي يقلل مساحة التغيير ويتيح rollback واضحاً.

## البدائل المرفوضة

- نقل كل شيء دفعة واحدة إلى `apps/` قبل وجود اختبارات عقود.
- إنشاء microservices منفصلة قبل قياس حدود الأداء والحاجة الفعلية.
- تثبيت مكتبات charts أو strategy builder قبل تحديد عقد بيانات candles وbacktest.

## تبعات القرار

سيظهر لبعض الوقت مساران اسميان: البنية الحالية والبنية المستهدفة. هذا مقصود ومؤقت، ويجب ألا يُعتبر اكتمالاً لـMonorepo حتى يتم نقل التطبيق بعد نجاح CI.
